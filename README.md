# Modbus motor control

The Delta HMI is the Modbus RTU master. Configure slave **17**, **9600 baud, 8 data bits, even parity, 1 stop bit (8E1)** on USART1 (PA9 TX, PA10 RX). The STM32 uses a 9-bit UART word length because parity occupies one bit.

USART1 interrupts must be enabled at priority 5 and dispatched through `USART1_IRQHandler()` to `HAL_UART_IRQHandler(&huart1)` for Modbus RX/TX callbacks to run. The CubeMX configuration includes this interrupt. Modbus initialization creates RTOS objects after `osKernelInitialize()` and before the motor task. If enabling from the HMI still fails, watch `modbusHandle.u16InCnt` for received frames, `modbusHandle.u16OutCnt` for replies, `huart1.ErrorCode` for UART errors, and bit 0 of `modbusCoilsData[0]` for the enable command. A set enable bit with no motion points to the GPIO/PWM/driver path rather than the HMI command binding.

| Data | Zero-based wire address | Function codes | Meaning |
| --- | --- | --- | --- |
| Motor enable (coil) | 0 | 01 read, 05/15 write | 0 stop, 1 run |
| Motor direction (coil) | 1 | 01 read, 05/15 write | 0 forward, 1 backward |
| Motion tracking enable (coil) | 2 | 01 read, 05/15 write | 0 pause tracking, 1 track |
| Zero motion estimates (coil) | 3 | 01 read, 05/15 write | Write 1 to zero; firmware clears to 0 on completion |
| Discrete inputs | 100–115 | 02 read | Reserved; initially zero |
| Estimated speed | 200–201 | 04 read | Signed 32-bit mm/s |
| Estimated position | 202–205 | 04 read | Signed 64-bit mm, from boot or last zero |
| Requested speed | 300 | 03 read, 06/16 write | Unsigned 16-bit mm/s, default 100; zero pauses pulses |
| Relative travel | 301–304 | 03 read, 06/16 write | Signed 64-bit mm, high word first; default zero means continuous motion |

Set direction coil 1, then enable coil 0. Stop by clearing coil 0. FC15 can update both coils together. Coil 2 enables pulse speed/position tracking and does not affect motor control. Both directions count while enabled: forward adds, backward subtracts. Disabling tracking retains position, ignores further travel, and reports zero speed. Re-enabling resumes from that retained position; movement during the pause is lost. Position starts at zero on boot, with no persistence.

`MotorControlHMI.dpa` uses Delta's RTU Hex Address driver: telemetry must use **R-C8** (speed, decimal address 200) and **R-CA** (position, decimal address 202), with signed values, high words first, and three decimal places. `RW-` selects holding registers (FC3), so using it for telemetry causes an illegal-address response. Buttons use **RWB-0** through **RWB-3** for the four control coils. The existing slider writes **RW-12C** (holding register 300); its values now mean unsigned integer mm/s. Update its label and operating range in DOPSoft; the packed HMI layout is unchanged. A signed travel input has not been added to the panel. Write registers 301–304 together using FC16 while disabled, then enable. Run `python3 tests/test_hmi_config.py` to check the packed HMI bindings. Open, compile, and download the updated project with DOPSoft to apply it to the panel.

Set coil 3 to 1 to zero the distance and speed. The tracking task resets its counters and speed sampling baseline, publishes zeros to registers 200–205, then clears only coil 3 under the same Modbus semaphore. Read coil 3 returning to 0 as completion acknowledgement. The request works while tracking is paused or the motor is stopped. While moving, tracking resumes immediately from zero and the next sample can be nonzero; zeroing does not stop the motor. Normally completion takes up to 100 ms; semaphore contention leaves the request pending until a successful acquisition.

`MotorControlTask` watches speed and coils every 10 RTOS ticks (10 ms at the current tick rate). It copies commands under the Modbus semaphore and releases it before GPIO/PWM operations or delays. Starting, changing speed, and reversing stop PWM and wait 10 ticks after setting direction, then recheck live speed and enable (also direction for continuous motion). A changed command or failed recheck leaves PWM stopped until a later poll. A failed initial read retains current motion. This is a pause, not a speed ramp.

On an observed enable rising edge, a nonzero relative travel command latches distance and direction: positive means forward, negative means backward, overriding coil 1. Distance and direction edits apply to the next finite move; speed updates apply during the move. Clearing enable cancels remaining travel. Speed zero pauses pulses without cancelling; a later nonzero speed resumes. Zero travel selects continuous motion, with direction controlled live by coil 1. Commands that toggle entirely between successful polls may not be observed.

Finite travel is rounded to the nearest whole pulse (at least one pulse). A separate remaining-pulse counter runs regardless of tracking coil 2 and is unaffected by telemetry zeroing. The final STEP edge disables the driver and stops PWM in the interrupt. The motor task then clears only enable coil 0 under the Modbus semaphore as completion acknowledgement; contention delays acknowledgement but does not restart the move. Wait for enable to clear before submitting the next move. Register readback retains requested speed and travel, including speed values outside the effective range. For example, +100 mm is `0000 0000 0000 0064`, and -100 mm is `FFFF FFFF FFFF FF9C` at 301–304.

The board starts disabled. Forward drives PB10 high, backward drives it low; PB11 is active-low enable, initialized high. TIM3 channel 1 (PA6) uses a 100-count period and 50% duty cycle. Conversion is `frequency Hz = requested speed mm/s / MOTION_MM_PER_PULSE`; nonzero commands are clamped to 100–700 Hz and rounded to integer Hz, then the prescaler rounds to the nearest divider. With the current calibration, 100 mm/s requests 141 Hz and produces about 141.093 Hz (99.73 mm/s); 700 Hz produces about 701.754 Hz. Nonzero low-speed requests therefore run at approximately 70.686 mm/s minimum, and the maximum is approximately 496.041 mm/s. Zero bypasses clamping and stops pulses. GPIO/PWM polarities, final pulse width, and driver response need hardware verification.

PWM mode 2 starts each cycle low; its compare interrupt matches the rising STEP edge. Every restart resets the timer counter and clears stale compare/pending interrupt state. Direction changes disable the driver during the startup pause; there is no calibrated deceleration or mechanical brake.

Commands remain latched until overwritten: disconnecting the HMI does not stop motion. The library's timeout is not a slave communication-loss watchdog. Use the physical stop/interlocks required by the machine; communication-loss stopping is not implemented here.

`EN_Port = NULL` assumes a serial interface that needs no firmware-controlled RS-485 direction pin (for example, an automatic-direction transceiver). Never connect STM32 UART pins directly to RS-485 signals. Configure the appropriate transceiver and DE pin if your hardware needs it.

`MotionTrackingTask` samples every 100 RTOS ticks (100 ms at the current 1 kHz tick rate), calculates signed speed using actual elapsed milliseconds, and publishes all six registers together under the Modbus semaphore. Speed and distance are integers in mm/s and mm, truncating toward zero at 1 mm/s and 1 mm resolution. Speed is averaged over the sampling interval; stopped motion or disabled tracking reports zero. Net forward/backward pulses within one interval can cancel. A failed semaphore acquisition leaves registers unchanged until a later sample publishes the latest position and rate; pulse accounting continues.

Read addresses 200–205 together with FC4 for a consistent snapshot. Multi-register values use two’s complement, most significant 16-bit word first. Configure the HMI to display both raw values directly as **mm/s** and **mm**, with no division. For example, raw speed 70 displays 70 mm/s; raw distance -1 (`FFFF FFFF FFFF FFFF`) displays -1 mm. Addresses and signed word order stay the same, but the units have changed from micrometres to millimetres; remove the previous /1000 scaling from existing HMI displays. Coil 2 changes take effect when the motor task successfully polls it, normally within 10 ms; motor startup also rechecks it after the direction pause. HMI readings normally update within 100 ms after that. Semaphore contention can extend either delay.

TIM3 IRQ priority 5 allows short FreeRTOS critical sections to protect the counter and account for pending edges at stop or tracking changes. The ISR performs only integer counting. Confirm the driver steps on the rising edge of PA6, and compare PA6 pulses against the counter on hardware, including starts, stops, and reversals.

Conversion currently uses a **22.5 mm wheel radius**, **200 pulses per motor revolution** (full steps at 1.8°), and an assumed **1:1 gear ratio**. This gives approximately **0.706858 mm/pulse** and **70.685 mm/s** at 100 pulses/s. The ISR still counts pulses; telemetry conversion happens in the tracking task, using total pulses for distance to avoid accumulating per-pulse rounding error. Distance saturates at the signed 64-bit register limit.

Calibration constants are together in the `USER CODE BEGIN PD` section of `Core/Src/main.c`: `WHEEL_RADIUS_MM`, `MOTOR_PULSES_PER_REV` (include driver microstepping), and `MOTOR_REVS_PER_WHEEL_REV` (motor revolutions needed for one wheel revolution; for a 5:1 reduction, use 5.0). Distance per pulse is `2 × π × radius / (pulses per motor revolution × motor revolutions per wheel revolution)`.

Finite pulse stopping does not measure mechanical overrun. The actual gearing is unknown, so the physical readings remain provisional until calibration constants are corrected. These values estimate commanded travel: missed steps, driver faults, and rope slip are not detected.

Run the host checks with `python3 tests/test_motor_control.py` and `python3 tests/test_motion_tracking.py` (including speed conversion, signed travel, pulse stopping, command races, and error paths in the motor test). Build firmware with `cmake --build --preset Debug` using the STM32 toolchain. The RTOS heap is 6144 bytes to accommodate the motor control and motion tracking tasks, default task, Modbus, idle, and timer tasks.
